Risheh V2 — UX Flow Specification

1. Product Context

Risheh یک Digital Studio مستقل است که در تقاطع Strategy، Branding، Digital Design، Web Development و Growth فعالیت می‌کند.

هدف سایت:

* معرفی واضح و متمایز Risheh
* ایجاد اعتماد
* نمایش کیفیت و رویکرد کاری
* معرفی خدمات
* نمایش Selected Work / Case Studies
* انتقال شخصیت و فلسفه برند
* تبدیل بازدیدکننده مناسب به Lead / Contact

سایت باید بیشتر شبیه یک Digital Studio با هویت مستقل و Art Direction قوی باشد، نه یک Corporate Website یا SaaS Landing Page.

⸻

2. Primary User Goals

کاربر باید بتواند با کمترین friction:

1. بفهمد Risheh چیست.
2. بفهمد چه خدماتی ارائه می‌دهد.
3. کیفیت کارها را بررسی کند.
4. با رویکرد و فلسفه Risheh آشنا شود.
5. تشخیص دهد آیا Risheh برای پروژه او مناسب است یا نه.
6. در صورت علاقه، برای همکاری اقدام کند.

⸻

18. Scroll Flow

Scroll یکی از ابزارهای اصلی storytelling سایت است.

اصول:

* Scroll باید narrative را جلو ببرد.
* Animation نباید مانع reading شود.
* User باید همیشه احساس کنترل داشته باشد.
* هیچ محتوای مهمی نباید فقط از طریق animation قابل دسترسی باشد.
* Scroll-based effects باید graceful degradation داشته باشند.

⸻

19. Interaction Hierarchy

Interactionها سه سطح دارند:

Level 1 — Essential

برای navigation و usability ضروری هستند.

Examples:

* Links
* Buttons
* Menu
* Form
* Navigation

این interactionها باید همیشه reliable باشند.

Level 2 — Contextual

برای افزایش clarity یا feedback.

Examples:

* Hover
* Focus
* Expand
* Active states

Level 3 — Experiential

برای ایجاد شخصیت و تجربه.

Examples:

* Scroll animation
* Image transitions
* Text reveals
* Parallax
* Cursor interactions

Level 3 نباید usability را مختل کند.

24. Accessibility Flow

تمام journeyهای اصلی باید بدون interaction پیچیده قابل استفاده باشند.

Requirements:

* Keyboard navigation
* Visible focus states
* Semantic HTML
* Accessible buttons and links
* Form labels
* Error messaging
* Reduced motion support
* Sufficient contrast
* Touch-friendly controls

اگر animation غیرفعال شود، flow باید همچنان کامل باشد.

⸻

25. Responsive Flow

UX باید در تمام breakpointها یکسان باقی بماند اما presentation می‌تواند تغییر کند.

Desktop:

* Larger compositions
* Hover interactions
* Multi-column layouts
* Expanded navigation

Tablet:

* Simplified composition
* Reduced density

Mobile:

* Single-column priority
* Touch-first interactions
* Compact navigation
* Reduced animation complexity
* Clear content hierarchy

اصل:

Same experience logic, different spatial expression.

⸻

26. Motion UX Principles

Motion باید سه کار انجام دهد:

1. Guide
2. Connect
3. Delight

Motion نباید صرفاً برای decoration استفاده شود.

هر animation باید یکی از این سؤال‌ها را پاسخ دهد:

* چه چیزی تغییر کرد؟
* کاربر باید به کجا نگاه کند؟
* چه چیزی به چه چیزی متصل است؟
* آیا interaction feedback لازم است؟

⸻

27. Reduced Motion

در صورت فعال بودن prefers-reduced-motion:

* Scroll animation کاهش یابد یا حذف شود.
* Parallax حذف شود.
* Transitionهای غیرضروری کاهش یابند.
* Content همچنان به صورت کامل قابل دسترسی باشد.

29. UX Principles

1. Clarity before novelty.
2. Content must remain accessible without animation.
3. Interaction should support the story.
4. Visual experimentation must not damage usability.
5. Navigation must remain predictable.
6. CTAs should be intentional, not excessive.
7. Mobile is a first-class experience.
8. Every interaction needs a meaningful purpose.
9. Never hide essential information behind unnecessary interaction.
10. The website should feel like Risheh, not like a generic agency template.

⸻

30. UX Acceptance Criteria

The UX is considered successful when:

* A new visitor understands Risheh’s positioning quickly.
* The user can reach Work within one obvious interaction.
* The user can understand the service offering without excessive exploration.
* Case Studies are easy to discover and navigate.
* Contact is always reasonably accessible.
* The contact flow has minimal friction.
* Navigation remains understandable on mobile and desktop.
* Animation enhances rather than blocks content.
* The complete experience remains usable with reduced motion.
* Users never reach a confusing dead end.
* Every major page has a clear next action.
